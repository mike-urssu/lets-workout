## 01. 프로젝트 개요

### 1.1 문서 개요
- 정의하는 것: Let's Workout 서비스의 **인증 기능**이 무엇을 해야 하는지(로그인, 로그아웃, 로그인 유지, PIN 연속 실패 잠금, 한 기기 로그인 규칙).
- 정의하지 않는 것: 인증 방식의 기술 선택(토큰 형식, 저장 방식, 암호화 알고리즘), API 상세 설계, DB 스키마(→ 설계 문서에서 다룸). 계정 발급·관리 방법(서비스 밖에서 운영자가 처리, 8.2).
- 대상 독자: 백엔드 개발자, 모바일 클라이언트 개발자, 테스트 담당자, 운영자.

### 1.2 서비스 / 기능 개요
사용자는 스스로 가입하지 않는다. 운영자가 사용자에게 아이디와 숫자 6자리 PIN을 발급하고, 사용자는 앱에서 그 아이디와 PIN으로 로그인한다. 한 번 로그인하면 앱을 쓰는 동안 로그인 상태가 계속 유지되고, 한 계정은 한 기기에서만 로그인 상태일 수 있다.

| 기능 영역 | 설명 | 관련 요구사항 |
|----------|------|--------------|
| 로그인 | 아이디와 PIN으로 로그인한다. PIN을 연속으로 틀리면 일정 시간 로그인이 잠긴다. | REQ-AUTH-001 |
| 로그아웃 | 지금 기기의 로그인을 끝낸다. | REQ-AUTH-002 |
| 로그인 유지 | 앱을 다시 열어도 로그인 상태가 유지되고, 사용할 때마다 유지 기간이 연장된다. | REQ-AUTH-003 |

### 1.3 외부 시스템 / 연동
- 해당 없음 — 외부 계정 서비스(소셜 로그인), 메일·문자 발송이 필요 없다.

## 02. 사용자 / 권한

### 2.1 사용자 유형
| 사용자 유형 | 설명 |
|------------|------|
| 비로그인 사용자 | 로그인하지 않은 사용자. 로그인 화면만 쓸 수 있다. |
| 일반 사용자 | 운영자에게 계정을 발급받아 로그인한 사용자. |
| 운영자 | 계정을 발급·관리하는 사람. **서비스 안에서는 역할이 없다.** 계정 관리는 서비스 밖에서 한다(8.2). |

### 2.2 권한 규칙
| 기능 | 비로그인 | 일반 사용자 |
|------|---------|-----------|
| 로그인 | ○ (발급받은 계정, 잠금 상태가 아닐 때만) | — (이미 로그인됨) |
| 로그아웃 | ✕ | ○ (지금 기기의 로그인만) |
| 로그인 유지 | ✕ | ○ (만료 전, 지금 기기가 그 계정의 로그인 기기일 때만) |
| 로그인이 필요한 기능(예: 운동 기록) | ✕ | ○ |

- 계정은 운영자만 만들 수 있다. 사용자는 스스로 가입할 수 없다. (BR-001)
- 한 계정은 한 기기에서만 로그인 상태일 수 있다. 다른 기기에서 로그인하면 이전 기기의 로그인은 끝난다. (BR-005)
- 사용자는 자기 PIN을 바꾸거나 다시 설정할 수 없다. PIN을 잊으면 운영자에게 재발급을 받는다(8.2).

## 03. 사용자 시나리오 / 화면 흐름

### 3.1 시나리오: 앱을 열고 로그인한다
```
앱 실행
        ↓
로그인 상태가 유지되고 있는가?
   ├─ 예 → 로그인 유지 기간 연장 → [홈 화면] (workout-session WO-001)
   └─ 아니오 (처음 실행, 로그아웃, 만료, 다른 기기에서 로그인됨)
        ↓
[로그인 화면]
        ↓
사용자가 아이디와 PIN 6자리를 입력한다. PIN 6자리를 다 입력하면 로그인을 시도한다.
        ↓
   ├─ 성공 → 이 기기를 그 계정의 로그인 기기로 정하고, 다른 기기의 로그인은 끝낸다 → [홈 화면]
   ├─ 아이디 또는 PIN이 틀림 → 실패 안내, 연속 실패 횟수 증가 → [로그인 화면]
   └─ 잠금 상태 → 잠금 안내와 다시 시도할 수 있는 시각 → [로그인 화면]
```

### 3.2 시나리오: 로그아웃한다
```
[홈 화면] 위쪽 로그아웃 버튼 (workout-session WO-001)
        ↓
사용자가 로그아웃을 누르고, "로그아웃 하시겠어요?" 확인 팝업에서 로그아웃을 누른다. (취소하면 아무 일도 없다)
        ↓
이 기기의 로그인을 끝낸다.
        ↓
[로그인 화면]
```

### 3.3 시나리오: 다른 기기에서 로그인되어 로그아웃된다
```
기기 A에서 로그인 중
        ↓
같은 계정으로 기기 B에서 로그인한다.
        ↓
기기 A의 로그인이 끝난다. (BR-005)
        ↓
기기 A에서 다음 요청을 보낸다.
        ↓
인증 오류, 다른 기기에서 로그인되어 로그아웃되었다는 안내 (ERR-006)
        ↓
[로그인 화면] (기기 A)
```

### 3.4 화면 정의

#### AUTH-001 로그인
- 진입 조건:
  - 로그인 상태가 아님 (앱 첫 실행, 로그아웃, 로그인 만료, 다른 기기 로그인으로 종료)
- 사용자 행동:
  - 아이디 입력
  - PIN 6자리 입력
  - 로그인 (따로 누르는 버튼 없이, PIN 6자리를 다 입력하면 시도한다)
- 시스템 동작:
  - 아이디와 PIN을 확인한다.
  - 잠금 상태인지 확인한다.
- 화면 데이터:
  - 아이디
  - PIN (입력한 숫자가 화면에 그대로 보이지 않아야 한다. 입력한 자리마다 점으로 보여준다)
  - 오류 안내 (로그인 실패, 잠금과 다시 시도할 수 있는 시각, 로그인 만료, 다른 기기 로그인으로 종료)
- 다음 화면:
  - 홈 (workout-session WO-001)
- 관련 요구사항: REQ-AUTH-001

## 04. 기능 요구사항

### 4.1 기능 목록
| ID | 기능명 | 사용자 | 관련 화면 |
|----|-------|-------|----------|
| REQ-AUTH-001 | 로그인 | 비로그인 사용자 | AUTH-001 |
| REQ-AUTH-002 | 로그아웃 | 일반 사용자 | workout-session WO-001 |
| REQ-AUTH-003 | 로그인 유지 | 일반 사용자 | 없음 (앱 실행·사용 중 자동) |

### 4.2 기능 상세

#### REQ-AUTH-001 로그인
- **목적:** 운영자에게 발급받은 아이디와 PIN으로 사용자를 확인하고, 이 기기에서 로그인 상태를 시작할 수 있어야 한다.
- **사전 조건:**
  - 로그인 상태가 아니어야 한다.
- **사용자 행동:**
  1. 로그인 화면에서 아이디를 입력한다.
  2. PIN 6자리를 입력한다.
  3. 로그인을 누른다.
- **입력:**
  - 아이디
  - PIN
- **처리 규칙:**
  - 아이디는 발급한 값과 정확히 일치해야 한다. 대소문자도 구분한다. (BR-002)
  - 아이디와 PIN이 모두 있어야 하고, PIN은 숫자 6자리여야 한다. 형식이 틀리면 확인하지 않고 거절하며 실패 횟수에 넣지 않는다. (BR-003, ERR-002, ERR-003)
  - 계정이 잠금 상태면 PIN이 맞아도 로그인하지 않는다. (BR-009, ERR-004)
  - 아이디가 없거나 PIN이 틀리면 로그인하지 않고, 해당 계정의 연속 실패 횟수를 1 늘린다. 어느 쪽이 틀렸는지는 알려주지 않는다. (BR-010, ERR-001)
  - 연속 실패 횟수가 5회가 되면 계정을 5분 동안 잠근다. (BR-007)
  - 아이디와 PIN이 맞으면 연속 실패 횟수를 0으로 되돌린다. (BR-008)
  - 이 기기를 그 계정의 로그인 기기로 정하고, 다른 기기에 있던 로그인은 끝낸다. (BR-005)
  - 로그인 유지 기간을 시작한다. (BR-006)
- **결과:**
  - 이 기기에서 로그인 상태가 시작되고 홈 화면으로 이동한다.
  - 다른 기기에서 로그인 중이었다면 그 기기의 로그인은 끝난다.
- **예외:**
  - 아이디 또는 PIN이 틀리면 로그인 실패를 알린다. (ERR-001)
  - PIN 형식이 틀리면 입력값 오류를 알린다. (ERR-002)
  - 아이디나 PIN이 빠졌으면 입력값 오류를 알린다. (ERR-003)
  - 잠금 상태면 잠금 오류와 다시 시도할 수 있는 시각을 알린다. (ERR-004)
- **관련 화면:** AUTH-001

#### REQ-AUTH-002 로그아웃
- **목적:** 사용자가 지금 기기에서 로그인을 끝낼 수 있어야 한다.
- **사전 조건:**
  - 로그인 상태여야 한다.
- **사용자 행동:**
  1. 홈 화면 위쪽의 로그아웃 버튼을 누른다.
  2. 확인 팝업에서 로그아웃을 누른다.
- **입력:**
  - 없음 (지금 기기의 로그인 정보)
- **처리 규칙:**
  - 지금 기기의 로그인을 끝낸다. 이후 이 기기의 로그인 정보로는 로그인이 필요한 기능을 쓸 수 없다.
  - 이미 끝난 로그인(만료, 다른 기기 로그인으로 종료)으로 로그아웃해도 오류 없이 로그아웃된 것으로 처리한다.
- **결과:**
  - 이 기기의 로그인이 끝나고 로그인 화면으로 이동한다.
- **예외:**
  - 없음 (이미 끝난 로그인도 성공으로 처리)
- **관련 화면:** workout-session WO-001 (로그아웃 버튼, 확인 팝업), 다음 화면 AUTH-001

#### REQ-AUTH-003 로그인 유지
- **목적:** 사용자가 앱을 쓰는 동안에는 다시 로그인하지 않아도 되도록 로그인 상태를 유지할 수 있어야 한다.
- **사전 조건:**
  - 이 기기에서 로그인한 적이 있어야 한다.
  - 로그인이 만료되지 않았고, 이 기기가 그 계정의 로그인 기기여야 한다.
- **사용자 행동:**
  1. 앱을 실행하거나 앱을 사용한다. (따로 누르는 것 없음)
- **입력:**
  - 없음 (이 기기의 로그인 정보)
- **처리 규칙:**
  - 앱을 실행하면 로그인 상태가 유지되고 있는지 확인한다. 유지되고 있으면 로그인 화면 없이 홈으로 간다.
  - 로그인 상태에서 앱을 사용하면 유지 기간을 사용 시점부터 다시 연장한다. (BR-006)
  - 마지막 사용 후 30일이 지나면 로그인이 만료된다. (BR-006)
  - 다른 기기에서 같은 계정으로 로그인하면 이 기기의 로그인은 더 이상 유지되지 않는다. (BR-005)
- **결과:**
  - 로그인이 유지되고 유지 기간이 연장된다.
- **예외:**
  - 로그인이 만료되었으면 인증 오류와 다시 로그인하라는 안내 후 로그인 화면으로 이동한다. (ERR-005)
  - 다른 기기 로그인으로 끝났으면 인증 오류와 그 사유를 안내한 뒤 로그인 화면으로 이동한다. (ERR-006)
  - 운영자의 PIN 재발급이나 계정 삭제로 끝났으면 인증 오류와 다시 로그인하라는 안내 후 로그인 화면으로 이동한다. (BR-011, ERR-008)
- **관련 화면:** 없음 (자동 처리), 실패 시 AUTH-001

## 05. 데이터 요구사항

#### DATA-001 계정
- 설명: 운영자가 발급한 사용자 계정 하나
- 관리해야 하는 정보: 아이디, PIN(평문, 8.2), 연속 실패 횟수, 잠금이 풀리는 시각, 발급 시각
- 관계: 한 계정은 0개 또는 1개의 로그인을 가진다(BR-005). 운동 기록 등 사용자 데이터가 이 계정에 속한다.
- 생명주기: 운영자가 서비스 밖에서 만든다 → 로그인에 쓰인다 → 운영자가 PIN을 재발급하거나 삭제한다(서비스 밖). 이때 그 계정의 로그인은 즉시 끝난다(BR-011). 삭제하면 그 사용자의 운동 기록 등 모든 데이터도 함께 삭제된다(BR-012)
- 관련 규칙: BR-001, BR-002, BR-003, BR-007, BR-008, BR-011, BR-012

#### DATA-002 로그인
- 설명: 한 계정이 한 기기에서 로그인한 상태
- 관리해야 하는 정보: 계정, 로그인한 시각, 마지막으로 사용한 시각, 만료 시점
- 관계: 하나의 계정에 속한다. 계정마다 많아야 하나다. (BR-005)
- 생명주기: 로그인 시 생성(같은 계정의 이전 로그인은 끝남) → 사용할 때마다 만료 시점 연장 → 로그아웃, 만료, 다른 기기 로그인, 운영자의 PIN 재발급·계정 삭제로 끝남
- 관련 규칙: BR-005, BR-006, BR-011

## 06. 비즈니스 규칙 / 예외

### 6.1 비즈니스 규칙
- **BR-001** 계정은 운영자만 만들 수 있다. 사용자가 스스로 가입하는 기능은 없다.
- **BR-002** 아이디는 서비스 안에서 하나뿐이다. 형식은 `이름.성`(영문)이고, 같은 아이디가 이미 있으면 끝에 2부터 번호를 붙인다. 예: `joonhee.song`, `joonhee.song2`. 로그인할 때 아이디는 발급한 값과 정확히 일치해야 한다(대소문자 구분).
- **BR-003** PIN은 숫자 6자리다.
- **BR-004** ~~시스템은 PIN을 원래 값을 알아낼 수 없는 형태로만 보관한다.~~ **폐기 (2026-10-05)** — 운영자가 PIN을 직접 관리하기 위해 평문으로 저장하기로 했다(8.2).
- **BR-005** 한 계정은 한 기기에서만 로그인 상태일 수 있다. 다른 기기에서 로그인에 성공하면 이전 기기의 로그인은 끝난다.
- **BR-006** 로그인은 마지막으로 사용한 때부터 30일이 지나면 만료된다. 사용할 때마다 30일이 다시 시작된다. 계속 사용하는 동안에는 기간 상한 없이 유지된다. (TODO-002 결정)
- **BR-007** 한 계정에서 PIN을 5회 연속으로 틀리면, 그 계정은 5분 동안 로그인할 수 없다. 5분이 지나면 자동으로 풀린다.
- **BR-008** 로그인에 성공하면 연속 실패 횟수는 0이 된다. 잠금이 풀린 뒤에도 0부터 다시 센다.
- **BR-009** 잠금 상태에서는 올바른 PIN을 입력해도 로그인되지 않는다.
- **BR-010** 로그인 실패 시 아이디가 틀렸는지 PIN이 틀렸는지 구분해서 알려주지 않는다. 다른 사람이 어떤 아이디가 있는지 알아내지 못하게 하기 위해서다.
- **BR-011** 운영자가 PIN을 재발급하거나 계정을 삭제하면 그 계정의 로그인은 즉시 끝난다. 다음 요청부터 로그인이 필요한 기능을 쓸 수 없다.
- **BR-012** 계정을 삭제하면 그 사용자의 모든 데이터(운동 기록 포함)를 함께 삭제한다. 삭제한 데이터는 되돌릴 수 없다.

## 08. 범위 / 제약 / 미결정 사항

### 8.1 범위
- **포함:**
  - 아이디·PIN 로그인
  - 로그아웃
  - 로그인 유지와 연장
  - PIN 연속 실패 시 일정 시간 잠금
  - 한 계정 한 기기 로그인
- **제외:** (아래 기능은 요청이 있기 전까지 만들지 않는다)
  - 회원가입 (사용자가 스스로 계정 만들기)
  - 소셜 로그인(Apple, Google, Kakao 등), 이메일·전화번호 로그인
  - PIN 변경, PIN 재설정(사용자 스스로)
  - 이메일·문자 인증
  - 앱 안에서의 회원 탈퇴
  - 운영자 기능: 계정 발급, PIN 재발급, 잠금 해제, 계정 삭제를 위한 화면·기능 (서비스 밖에서 처리, 8.2)
  - 여러 기기 동시 로그인
  - 2단계 인증, 생체 인증(지문·얼굴)
  - 로그인 기록을 사용자에게 보여주는 화면
  - 관리자 역할과 역할별 권한

### 8.2 제약사항
- 계정 발급, PIN 재발급, 잠금 해제, 계정 삭제는 운영자가 서비스 밖에서 직접 한다. 서비스는 이를 위한 기능을 제공하지 않는다.
- 계정 정보(아이디, PIN 포함)는 평문으로 저장하고, 운영자가 DB에 직접 접근해 SQL로 관리한다. (2026-10-05 사용자 결정. 위험: DB나 백업이 유출되거나 DB 접근 권한이 있는 사람은 모든 PIN을 볼 수 있다. 보완책은 설계에서 정한다)
- 운동 기록 요구사항(`workout-common.md` 등)의 "로그인한 사용자"는 이 문서의 로그인을 뜻한다.
- Figma 디자인(2026-10-09 확인)과 다른 점:
  - 로그인 실패 문구는 디자인대로 "PIN이 올바르지 않습니다. 다시 입력해 주세요."이다. 디자인은 PIN이 틀린 경우만 보여주지만, 없는 아이디에도 같은 문구를 써서 아이디가 있는지 드러내지 않는다(BR-010, 2026-10-09 사용자 결정). 그래서 아이디를 잘못 쓴 사용자도 PIN이 틀렸다는 안내를 받는다.
  - 아이디 입력란 이름이 "사용자 이름"이다. 이 문서의 "아이디"와 같은 것이다.
  - 잠금(ERR-004), 로그인 만료(ERR-005), 다른 기기 로그인으로 종료(ERR-006) 안내는 디자인이 없다.
